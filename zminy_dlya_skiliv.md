# Зміни для скілів

Правила, які перевіряють моди elena-workspace, сформульовано так, щоб агент виконував їх у будь-якому середовищі, зокрема у звичайному чаті. Кожна зміна: скіл, точний наявний фрагмент, новий текст.

Уже є в скілах, змін не потрібно:
- серединна крапка, крапка з комою між реченнями, «,0», десяткова кома: `academic-pipeline`, розділ 11 (самоперевірка) і лінтер;
- поля `created_by: Claude` і `verification: не перевірено`, заборона змінювати `.obsidian/`, дозвіл доповнювати картки проєктів, створені Claude: `obsidian-knowledge-base`, розділ 1;
- метрики вносить лише користувачка, повний транскрипт чужого відео не копіюється: `obsidian-knowledge-base`, розділ 4;
- залишок ліміту Wiley записується в `stan.md`: `academic-office`, розділ 10.

Рядок стану, панелі, сповіщення, теми і банер є механікою мода, правил для скілів не потребують.

---

## 1. ukrainian-proofreading-editor: кодова перевірка і запис у stan.md

**Наявний фрагмент** (розділ 11):

```
9. Фінальне контрольне вичитування всього тексту та перевірка цілісності всіх посилань.
```

**Новий текст:**

```
9. Фінальне контрольне вичитування всього тексту та перевірка цілісності всіх посилань.
10. Кодова перевірка тексту файлу після вичитування: немає серединної крапки «·»; немає речень, з'єднаних крапкою з комою (поза квадратними дужками посилань і списком джерел); немає «,0» у цілих значеннях; немає десяткової крапки в українському тексті (поза DOI, URL і References); немає літер «ы», «э», «ъ», «ё». Знайдене виправляєш до видачі. Кожну заглушку «[уточнити]», що лишилася, називаєш у звіті.
11. Якщо вичитування є етапом конвеєра `academic-pipeline`, після нього записуєш у `stan.md` рядок «Фінальне вичитування за ukrainian-proofreading-editor: виконано». Без цього запису файл не видається.
```

## 2. academic-pipeline: перевірка перед видачею

**Наявний фрагмент** (етап 10):

```
### Етап 10. Видача

1. Надішли файл через `SendUserFile`.
```

**Новий текст:**

```
### Етап 10. Видача

0. Перед надсиланням перевір кодом текст фінального .docx (python-docx, з таблицями) за пунктом 10 розділу 11 скіла `ukrainian-proofreading-editor` і переконайся, що в `stan.md` є рядок «Фінальне вичитування за ukrainian-proofreading-editor: виконано». Якщо запису немає або знайдено порушення, файл не надсилається: спершу вичитування чи виправлення.
1. Надішли файл через `SendUserFile`.
```

## 3. academic-pipeline: фільтр за доменом

**Наявний фрагмент** (розділ 4.1, правило 8):

```
лише наукові джерела, офіційні й нормативні документи; без порталів, головних сторінок сайтів, Вікіпедії, неробочих посилань, бакалаврських робіт.
```

**Новий текст:**

```
лише наукові джерела, офіційні й нормативні документи; без порталів, головних сторінок сайтів, Вікіпедії, неробочих посилань, бакалаврських робіт. Посилання на домени .ru, .su, .by, .рф і на російські наукові платформи (eLibrary, КіберЛенінка, Dissercat, Лань, Юрайт, Znanium) у `dzherela.tsv` не вносяться, навіть якщо праця має український чи англійський опис.
```

## 6. obsidian-knowledge-base: вибір каналу

**Наявний фрагмент** (розділ 4, правила):

```
- перед новими ідеями прочитай `70_YouTube/00_Стратегія каналу/Стратегія каналу.md` і `70_YouTube/40_Аналітика/Що працює.md`;
```

**Новий текст:**

```
- перед будь-якою роботою з YouTube-скілами (хуки, сценарій, опис, транскрипт, ідея) спершу запропонуй користувачці обрати канал (каналів кілька), потім прочитай `70_YouTube/00_Стратегія каналу/Стратегія каналу.md` і `70_YouTube/40_Аналітика/Що працює.md` і працюй у межах стратегії обраного каналу;
- метрик, яких немає в картці, не оцінюй і не прогнозуй: порожнє поле лишається порожнім;
```
